# Delonix Seiva

A Rust backend framework for robust, high-criticality systems — backend only,
with the ease of FastAPI and NestJS, a production- and cluster-ready server, and
[DORM](https://github.com/ngolacloud/dorm) as the default data layer.

Seiva is part of the Delonix family: **Delonix Engine** (containers and
microVMs), **DORM** (the ORM), and **Delonix Seiva** (this framework).

## What makes Seiva different

- A project is made of **modules that own their data**. There is no business
  code outside a module.
- Each module is born with its own PostgreSQL schema and a ready data layer
  (models, migrations, repositories and support tables), registered
  automatically.
- The **same code** runs as a modular monolith or as a microservice, by
  configuration alone — no rewrite.
- Clean Architecture enforced by the compiler: five crates per module
  (`domain`, `application`, `facade`, `infrastructure`, `interface`), with the
  dependency rule imposed by the crate graph.
- Zero trust between modules, even in the same process: every facade call
  carries and verifies the caller's identity and the user context.

## DORM is the default, and optional

The DORM data layer is wired in and generated by default. You switch it off per
project or per module in `seiva.toml`; a module with an external data layer
brings in no ORM and owns its own connections with the libraries it chooses.

The framework **core never depends on DORM**: the ORM enters only through the
`seiva-data-dorm` gateway behind the `dorm` feature. The dependency is one-way —
Seiva depends on DORM, DORM never on Seiva.

## Status

Founding stage. The workspace carries the boundary (`seiva-ports`), the
framework entrypoint (`delonix-seiva`) and the CLI (`seiva`). Only `seiva
doctor` and `seiva --version` do real work today; every other command reports
the phase that will implement it. See [`docs/adr/0001-seiva-foundations.md`](docs/adr/0001-seiva-foundations.md)
for the foundations and [`docs/progress.md`](docs/progress.md) for the roadmap
state.
