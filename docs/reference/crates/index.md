# Crate reference

Seiva is a workspace of focused crates. The full type-level API is generated by
`cargo doc --workspace --no-deps`; this page is the map of what each crate owns.

## The framework

| Crate | Owns |
| --- | --- |
| `delonix-seiva` | The entrypoint downstream apps depend on: the `contract` descriptor + `schema` (`WireSchema`), the `facade`/`controller`/`WireSchema` macros (re-exported), the worker runtime, and a re-export of the ports. |
| `seiva-ports` | The trait-only boundary the application layer codes against: `UnitOfWork`, `EventPublisher`, `Clock`, `IdGenerator`. No runtime, no deps. |
| `seiva-macros` | The procedural macros: `#[facade]`, `#[controller]`, `#[derive(WireSchema)]`. |
| `seiva-http` | The HTTP transport: `router`/`router_with_modules`, the layer stack (request-id, security headers, authn, rate limit, CORS), RFC 9457 `Problem`, `Valid<T>`, the permission guard + `Scoped<T>`, health, `/docs`. (No `/admin`: that is the optional `seiva-console-admin` extension.) |
| `seiva-console-admin` | **Optional extension (ADR 0008), not a base dependency.** The admin console at `/admin`, generated from the live OpenAPI contract, self-contained with a strict hash-based CSP. A composition root mounts it with `seiva_console_admin::mount(router)`; a backend built without it has no `/admin`. |
| `seiva-openapi` | The OpenAPI 3.1 generator from facade descriptors (+ WireSchema). |
| `seiva-grpc` | The proto3 service generator from facade descriptors. |
| `seiva-identity` | The verified `Principal` and `Authenticator` (OIDC/JWT via JWKS). Transport-free. |
| `seiva-auth` | Password/credential primitives (Argon2id PHC). |
| `seiva-config` | Typed 12-factor `ServerConfig` + the `AppEnv` production guard. |
| `seiva-cqrs` | The application-layer command/query mediator + typed middleware. |
| `seiva-messaging` | The CloudEvents envelope + `Publisher` + broker backends. |
| `seiva-webhooks` | Standard Webhooks signing/verification. |
| `seiva-server` | The runtime: the serve loop, observability, graceful shutdown, worker host. |
| `seiva-testing` | In-memory test doubles for the ports (a dev-dependency). |
| `seiva-cli` | The installable `seiva` binary (scaffold, dev loop, lint, db, openapi/proto). |

## The data layer (DORM-coupled, feature-gated)

These couple to DORM and are built behind the `dorm` feature / on their own:

| Crate | Owns |
| --- | --- |
| `seiva-data-dorm` | The DORM gateway: `connect` + the four ports over DORM (the Gateway pattern — all DORM coupling lives here). |
| `seiva-outbox-relay` | The transactional-outbox → broker relay worker. |

The example modules (`examples/notes`, `examples/accounts`) show the five-layer
shape the scaffolder emits.
